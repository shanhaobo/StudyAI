# 盲区：fp16 训练为什么必须配 GradScaler

**主题大类**：数值稳定性 / 精度

## 误区

要省显存就把模型 `.half()`、输入 `.half()`，跑起来 loss 突然变 NaN，或者训了几百 step loss 完全不降。以为是 fp16 表达能力差，回滚 fp32。

## 真相

fp16 的**指数范围只有 [~6e-5, 65504]**。问题出在两端：

1. **梯度下溢（underflow）**：很多深层网络的梯度会 < 6e-5，在 fp16 下直接变 0，参数原地不动。
2. **激活 / loss 上溢（overflow）**：偶发尖峰梯度 > 65504 → inf → NaN 全网络。

`torch.cuda.amp.GradScaler` 的招数（"loss scaling"）：

- 反传前把 loss × 一个大常数（如 65536）→ 所有梯度同步放大，远离下溢区。
- `optimizer.step()` 前再把梯度 ÷ 同样常数 → 数值上等价于不缩放。
- 检测到 inf/NaN 时**跳过这一步 + 自动降低 scale**，避免污染参数。

正确范式（PyTorch 标准）：

```python
Scaler = torch.cuda.amp.GradScaler()
for batch in DL:
    with torch.cuda.amp.autocast():        # 前向用 fp16
        out = Model(batch)
        Loss = LossFn(out, target)
    Scaler.scale(Loss).backward()          # 缩放后反传
    Scaler.step(Optimizer)                 # 自动 unscale + step（含 inf 检测）
    Scaler.update()                        # 调整 scale
```

注意 **autocast** 不是 `.half()`：autocast 选择性地把 op 跑成 fp16（matmul、conv 等），其余保留 fp32（reduce、softmax、loss）——比手动 `.half()` 安全得多。

bf16（`torch.bfloat16`）则不需要 GradScaler——指数位和 fp32 一样宽，只损失尾数精度，几乎不会下溢。新硬件（A100+/RTX 30+）建议直接 bf16。

## 直观比喻

> fp16 像一把**短的放大镜**：看小数字看不见（下溢），看大数字爆框（上溢）。
> GradScaler = 反传前**把整张图片放大一千倍**让小细节进入可见区，反传完再缩回来——参数学到的内容不变，但中间过程不再丢信息。

## 一句话记住

> **fp16 训练必配 `autocast + GradScaler`；bf16 不需要 scaler**。手动 `.half()` 是新手陷阱。
